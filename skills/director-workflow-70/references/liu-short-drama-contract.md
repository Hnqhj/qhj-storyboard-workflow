# Liu 真人短剧制作契约

这是 Liu 真人短剧 Seedance 2.5/2.0 工作流的唯一规则事实源。其他技能可补充专业方法，但不得覆盖本契约；若旧参考与本文件冲突，以本文件为准。

## 唯一入口与执行深度

- **档位是输入，不是执行层的判断。** `fast / standard / full` 与题材
  （`dialogue / mixed / action`）**主要由决策层——镜语**（`G:\工作\分镜` 的镜头组
  架构师专家包）判定，判定结果经控制台 task-context 传到执行层；用户显式指令
  可覆盖。`script-camera-group-router`
  只**读取**并据此选择链路，不得自行判定、推断或改档。
- 未收到档位时按 `standard` 执行并显式标注为假设（不回头从剧本反推档位）；
  档位装不下素材（时长压不下、P0/P1 阻塞）时，停下把命名阻塞报回调用方，
  由调用方重新定档。
- 深度只控制后台分析层数，不改变最终交付规格。
- 路由器必须先写 `ExecutionPlan`：精确列出允许/禁止加载的 Skill、唯一
  平台编译器、匹配的 preflight、`prompt_owner=narrative-camera-groups`
  与 `max_prompt_compile_count=1`。执行中不得擅自扩大白名单。
- `narrative-camera-groups` 是唯一镜头组边界与提示词结构 Owner；每组只
  允许一个选定平台编译器执行一次最终编译。交付检查和 preflight 只能
  返回问题或字段补丁，不得重新创作第二份完整提示词。
- 需要时效资料时仅由 `creative-research-first` 研究一次，并写一个
  `ResearchReceipt`；平台编译器和 preflight 复用回执，不得再次检索。

## 交付与分组

- 镜头组是连续场景单元：同一地点、同一时间连续性、同一空间布局与不中断的动作/对白线，默认归入一个镜头组，组内由多个镜头组成。剧情转折、台词换人、反应、景别或机位变化都属于组内覆盖，不能单独作为拆组理由。`14–28秒`仅为常用时长建议，单次生成绝不超过30秒；只有换场、明确时间跳跃、刻意封闭的场景交接或已验证的平台限制才允许拆分。平台限制导致的拆分应记为同一场景镜头组下的连续生成段，不得冒充新的镜头组。选择完成场景所需的最短时长，不为凑时长拖镜头。
- 单镜通常 `1–4秒`；长于4秒仅因完整对白、情绪停留、一镜到底动作或必要揭示成立。
- 每组先给人理解的镜头表，再给一份独立、完整、可复制、可生成的提示词；禁止紧凑版、压缩版、精简版、局部补丁或“见上组”。
- 每组提示词固定六段：`角色/资产锁定 -> 视觉材质总控 -> 镜头语言总控
  -> 事件节拍 -> 声音 -> 正向稳定约束`。六段都必须有当前组的有效内容。
- `事件节拍` 必须按 `镜头01｜起始-结束s`、`镜头02｜起始-结束s` 显式
  分块；每个镜头块下用连续的 `T=起始-结束s` 微节拍完整覆盖镜头时间，
  每个 T 段只承载一个可观察动作、表演、运镜、声音同步点或状态结果。
- 不得用“同上、沿用、参考镜头表、保持不变”代替独立细节。

## 台词与切镜

- 普通中文对白平均 `3字/秒`，常用范围 `2.8–3.2字/秒`；克制/情绪对白 `2–3字/秒`；急促短句可短暂 `3.5–4字/秒`。
- 优先让人物说完整一句或自然半句，在语义落点、停顿或换气处切镜；避免在一个词中间切断。这是软规则，突发动作、冲击、危险、打断、反应抢拍或信息揭示可提前切，但台词必须以声音桥保持可懂。
- 短台词不强制切反应。只有反应能新增信息、改变关系/权力、推动下一动作或制造悬念时才切；长台词和关键转折按需要安排听者/旁观者/道具反应。

## 景别与表演

- 常规覆盖优先 `全景/中景/近景（腰部以上）`；特写/大特写只用于强烈动作或能力峰值、决定性眼神、关键受力/接触或不可替代道具证据。
- 位置变化、走位、逼近、后退、落地、换位和复杂调度先用全景或中景交代；推镜头不直接推到人脸，近景保留肩背、手势、视线或关系对象。
- 表演必须保留换气、重心、预备、惯性、收势、反应延迟和次级衣料/发丝/道具运动；禁止木偶式静止、瞬间换姿、机械点头、同步动作和无理由手脚切换。

## 声音与角色资产

- 默认声音只保留人物台词、画外音和有明确物理来源的纯拟声音效。只有用户或权威剧本明确要求时才启用音乐、配乐、BGM、氛围铺底或情绪音效，并为其写明具体叙事功能与时点。
- 上传五视图角色在模型提示词中统一使用 `@角色名`；与剧本同时提供的参考图、参考视频和参考音频在模型提示词中统一使用 `@实际图片名`、`@实际视频名`、`@实际音频名`，首次出现紧跟中文职责说明，例如 `@废墟夜景.png（场景布局与光线参考）`。`{{Image N}}`、`{{Video N}}`、`{{Audio N}}`仅作后台编号映射，不作为最终提示词的主引用；不得擅自改名、编号替代或省略艾特。

## 预检

- 每镜必须有时间、时长、景别、机位/视高/角度、主运镜、焦段或镜头视角、光圈/景深与对焦主体、布光方向/光质/色温/阴影逻辑、动作/台词、切镜触发、承接和末帧状态。参数服务叙事和可读性，不得堆成摄影术语清单。
- 每组必须通过：时长连续、台词完整、动作因果、人物/空间连续、镜头可读、复杂度不过载、声音协议无违规。
- `fast` 只运行机械预检；`standard/full` 才运行完整专业预检。任何预检
  都检查现有 Prompt，不把全文重写计为检查步骤。
