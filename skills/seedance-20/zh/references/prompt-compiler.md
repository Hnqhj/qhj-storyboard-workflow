# 提示词编译器（Prompt Compiler）

编译器把内部项目状态转化为一条仅针对当前片段的自然语言 Seedance 提示词。JSON 或 YAML 可以组织规划，但发送给 Seedance 的最终提示词保持可读散文，除非用户明确请求结构化输出。

## 输入（Inputs）

- 项目状态；
- 当前片段契约；
- 平台提示词配置（surface prompt profile）；
- 参考转移契约；
- 延续用的观察源状态；
- 已完成和预留的节拍；
- 连续性锁定与允许的变化；
- 提示词预算。

## 编译顺序（Compile Order）

1. 血缘：仅在面向用户的契约或胶囊中命名 `project_id`、`clip_id` 和父级，如果浪费提示词预算，不一定要放进最终提示词。
2. 源角色：标识活动的参考标签及每个控制什么。
3. 实际开场状态：延续用观察到的素材，仅首片段用计划状态。
4. 当前片段动作：一个带终点的叙事任务。
5. 摄影机与运动阶段：当连续性重要时，纳入继承的矢量。
6. 光、环境、风格和音频：仅纳入状态关键或情绪关键的子句。
7. 排除项：已完成节拍和预留的未来节拍。
8. 终点：本片段必须到达的完成状态。

## 自然语言提示词规则（Natural-Language Prompt Rules）

不要把内部 JSON 发给 Seedance。不要包含所有未来片段。不要把计划中的结尾描述成已经发生。不要重演已完成的动作。不要执行预留的后续动作。不要编造确定性保证。

使用片段范围语言：

- 用 "Begin with..." 表示观察到的开场状态。
- 仅当存在源素材时用 "Continue the same..."。
- 用 "This clip only..." 表示当前叙事任务。
- 用 "Stop when..." 做终点控制。
- 用 "Do not yet..." 表示预留的未来节拍。

## 压缩（Compression）

当提示词必须缩短时，按此顺序保留：

1. 精确的参考标签和角色边界。
2. 实际开场状态。
3. 当前动作和终点。
4. 连续性锁定。
5. 已完成节拍排除项。
6. 预留节拍排除项。
7. 摄影机或开放运动矢量。
8. 音频阶段。

先删除通用风格增强词、重复形容词、未来故事摘要、参考中已可见的背景、次要动作和推测性内部备注。
