# 前端设计系统（Frontend Design System）

本仓库没有应用前端。面向用户的前端是 GitHub README、生成的位图资产和 SVG 辅助资产。

## 设计目标

- 干净、电影感、高对比的呈现。
- 不要折叠的 Markdown。
- 不要过载的霓虹文案。
- 在 GitHub 移动端与暗色模式下可用。
- 清晰的"从此开始"决策路径。
- 技能地图之后，验证命令在首屏内可见。

## 资产规则

- 简单的结构性辅助示意图使用 SVG。
- 当资产需要电影感纹理、真实场景纵深或视觉叙事时，README 主视觉、操作系统信息图、技能地图信息图、能力地图、CDN 分发地图、参考角色地图、生产交付地图和质检栈使用生成的位图图像。
- 位图主视觉/信息图/地图资产应无标识、无水印，且在 GitHub README 宽度下可读。
- 当标签大、短、修正且在图旁的无障碍 Markdown 中重复时，允许使用富文本信息图。
- SVG 资产必须包含 `<title>` 和 `<desc>`。
- SVG 资产中不得有外部脚本、图像、字体或追踪。
- 避免通用的镜头仪表盘、密集的装饰噪点和不可读的微型标签。
- 手动检查生成的文本；拒绝乱码词、丑陋的字体处理、低对比、嘈杂装饰和看起来像占位符的面板。

## README 规则

- 没有一行超过 500 个字符。
- 表格应有真实的换行。
- 每个主要章节都应回答一个用户决策：它是什么、我从哪里开始、有哪些技能、我如何验证、有什么变化。
- 位图主视觉应避免水印和细小文字。富文本信息图的标签也必须在 Markdown 中呈现，以便无障碍与搜索。

## 编辑设计令牌（v6 首页）（Editorial Design Tokens）

首页使用一套工作室规格表系统。把这些令牌应用到每个手工构建的矢量资产；绝不重新引入渐变、辉光团块或多色调点缀渐变。

| 令牌 | 暗色 | 亮色 |
|---|---|---|
| 背景 | `#100E0A` 暖墨 | `#F7F3EA` 暖纸 |
| 前景 | `#EDE6D6` | `#1C1914` |
| 弱化 | `#9A917D` | `#6F6757` |
| 发丝线 | `#2E2A22` | `#D8D0BE` |
| 点缀（单色） | `#E2A75E` 琥珀 | `#A86F24` 琥珀 |

- 展示字体：`Didot, 'Bodoni MT', 'Hoefler Text', Baskerville, 'Palatino Linotype', Georgia, serif`——在系统提供的情况下用高对比的编辑衬线体，Georgia 作为通用回退；字重 400，不用外部字体。标语以衬线斜体格言形式呈现，使用句首大写，而非等宽。
- 手写体点缀：`'Snell Roundhand', 'Apple Chancery', 'Gabriola', 'Segoe Script', 'Brush Script MT', cursive`——一条书法线只用一次，用于字标 `Skill OS` 的那一半，与雕刻感的 Didot `Seedance 2.0` 配对。这是唯一的花饰；其余一切保持克制。仅用系统手写体，不用外部字体，优雅回退到 `cursive`。让 `Seedance 2.0`、标语和所有规格标签都不用手写体，以保持报头可读。
- 规格字体：`ui-monospace, 'SF Mono', SFMono-Regular, Menlo, Consolas, monospace`——字重 400，更小尺寸，宽松字距（眉标上 6–7px）；标签低语，字标发声。
- 母题：齿孔条、取景器边角标记、十字准线、时间码、波形刻度——以精细线条绘制。
- 报头以主题感知的成对形式交付（`hero-dark.svg`、`hero-light.svg`），置于 `prefers-color-scheme` 的 picture 元素之后；操作示意图（`skill-map.svg`）自带背景，使其在两种主题下都可读。
- 不要把版本号或数量烤进矢量资产；它们会过时。使用永恒标签（ROUTE / VERIFY / DIRECT / DELIVER）。
- 生成的位图艺术仅供陈列。README 的工作界面是矢量。
