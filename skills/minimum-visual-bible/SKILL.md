## I — 方法论骨架（Interpretation）

Visual Bible 是项目的可执行视觉契约，不是参考图堆积，也不是越厚越专业。
先建立覆盖视觉方向、色彩情绪、角色、场景、道具、材质、灯光、构图与交付规格的“完整母版”，再按项目风险裁剪为最小版本。
裁剪原则不是看项目大小，而是看返工风险：会不会跨镜头复现、身份会不会漂、空间是否复杂、多人是否协作、是否混合实拍、是否跨平台交付。
每条规范都应包含可见定义、获批正例、必要反例、责任人和验收方式；只有形容词而没有锚点，不能形成约束。
Bible 在批量生产前通过代表性镜头试跑，失败就修订标准；通过后冻结版本，变更必须说明影响镜头与回归范围。
目标是用最少的规范消除最高代价的歧义，同时保留可探索变量，而不是把创作锁死。

## A1 — 课程中的应用（Past Application）

### 案例 1：把全故事画面排成色彩情绪版

- **问题**：单张画面可以好看，但故事从明亮、深入环境、粉色光到夜晚的情绪变化可能失去整体关系。
- **方法论的使用**：讲者先规划情绪阶段，以同一文字 Bible 生成多组画面，再按叙事顺序集中排列审看。
- **结论**：视觉标准必须覆盖时间轴和镜头之间的关系，而不能只审批孤立图片。
- **结果**：得到一套可比较的故事情绪版，为后续色彩和镜头方向提供共同基线；课程未展示完整成片，因此不推断最终效果。

### 案例 2：《石托岭》先收集参考并建立视觉方向

- **问题**：没有前置标定就进入生产，参考会在各镜头中被随意解释。
- **方法论的使用**：讲者围绕《石托岭》收集插画、书和分镜等材料，先建立视觉与音乐基线，再进入制作和节拍粗剪。
- **结论**：参考必须被转译成项目标准，而不是只保存作者名或作品名。
- **结果**：项目形成了可用的方向锚点；课程没有完整说明授权与参考转化边界，因此正式 Bible 还应补素材来源和使用许可。

## A2 — 触发场景（Future Trigger）

### 用户会在什么情境下需要这个 skill？

1. 准备从概念样片进入批量图片、视频或多镜头生产，需要先冻结共同视觉语言。
2. 同一角色、服装、道具、场景、材质、光线或色彩在不同镜头中持续漂移。
3. 多人或多个 Agent 各自产出合格，但合在一起像不同项目。
4. 需要判断 15 秒广告、连续短剧、混合实拍项目分别应保留哪些 Bible 字段。
5. 团队已经有 moodboard，却无法据此明确验收、返工或批准。

### 语言信号

- “先帮我做一份视觉 Bible / build a visual bible.”
- “这些镜头单看都好，放一起不统一 / keep the look consistent.”
- “角色和场景总在漂 / character and environment keep drifting.”
- “这个小项目需要写多完整的规范 / what is the minimum viable visual spec?”
- “把 moodboard 变成可执行标准 / turn references into an executable visual spec.”

### 与相邻 Skill 的区分

- `creative-north-star` 决定表达目标与不可让渡项；本 Skill 将其落实为全项目视觉控制面。
- `visual-calibration-loop` 专门组织视觉随叙事时间的变化；本 Skill 管理跨全项目的稳定规则、资产、规格和变更。
- `modular-text-bible` 只编码可复用文字接口；本 Skill 还包含参考锚点、资产、技术规格、审批和版本。
- `entity-continuity-system` 深化具体实体的身份、状态与历史；本 Skill 只规定最低连续性字段。

## E — 可执行步骤（Execution）

当 skill 被激活后，agent 按以下步骤执行：

1. **建立项目风险画像**
   - 记录片长/镜头数、重复主体、状态变化、空间复杂度、团队规模、生成渠道、混合实拍、交付平台和返工成本。
   - 完成标准：每项标为低/中/高，并写出证据；不得只用“项目很大/很小”概括。
   - 判停条件：若创作目标与不可让渡项尚未确定，先调用 `creative-north-star`。

2. **从完整母版裁剪字段**
   - 基础层至少包含：一句视觉命题、画幅/分辨率/交付、色彩与情绪、角色身份、关键场景/道具、材质与光线、构图原则、禁止项、资产命名/版本、批准流程。
   - 风险增强层按需加入：跨集状态、服装变化、空间图、表情/动作、多视图、镜头/深度数据、实拍匹配、平台适配和来源许可。
   - 完成标准：每个高风险项都有对应字段；每个保留字段都能解释它将避免哪类返工。

3. **把抽象词转成可见契约**
   - 每条规范写成“意图—可观察特征—获批正例—禁止反例—验收人”。
   - 例如不只写“压抑”，还要写明亮度区间关系、主光方向、色彩变化、空间密度和角色可读性。
   - 完成标准：两名未参与起草的人能对同一测试图得到一致的通过/不通过结论；若不能，继续具体化。

4. **建立批准锚点与资产索引**
   - 为关键角色、场景、道具、材质、情绪节点和交付形态各选至少一个获批锚点；记录来源、版本、适用镜头和不可复制部分。
   - 完成标准：生产人员和 Agent 能按稳定名称找到锚点，不使用“图 1”“上次那张”等临时指代。

5. **用代表性镜头试跑**
   - 选择 2–4 个覆盖最高风险的镜头：主角近景、全景空间、关键情绪转折、混合实拍或复杂材质。
   - 完成标准：试跑结果逐项对照 Bible；所有失败都被归类为规范缺失、资产缺失、工具不遵从或执行错误。
   - 判停条件：若高风险锚点未获批，不得进入全量生成；先修订字段或升级参考/layout/3D 输入。

6. **冻结最小版本并定义变更控制**
   - 删除试跑中无用的字段，保留能降低风险的字段；标记版本、负责人、冻结日期、例外和受影响镜头。
   - 完成标准：Bible 足以生成任务卡和验收清单；任何变更都能定位需要重测的资产与镜头。

## B — 边界（Boundary）

### 不要在以下情况使用此 skill

- 只做一次性、低风险草图且失败成本极低；先用轻量参考和快速原型验证即可。
- 故事、受众和创作意图尚未确定；视觉文档不能替代 `creative-north-star`。
- 用户只需模块化提示词或单镜头成像描述；应调用 `modular-text-bible`。
- 已有 Bible，只需定位一组镜头中的漂移；应调用 `cross-shot-consistency-audit`。

### 课程警告的失败模式

- **把视觉定调拖到后期**：没有获批锚点便批量生产，最后试图用 LUT 或滤镜修复上游方向冲突。
- **完整工业规范照搬所有项目**：大量字段从未使用，写文档时间超过原型时间，规范变成流程表演。
- **参考堆积但不转译**：只有图片和作者名，没有说明要保留的色、光、材质、构图或情绪属性。

### 讲者的盲点与时代局限

- 课程偏视觉和摄影；实际 Bible 可能还需声音、字幕、动效、表演、剪辑、版权、无障碍和品牌规范。
- Bible 只能提高共同理解，不保证生成模型遵从；必须通过代表性镜头验证，并为失败准备参考、layout、3D 或人工制作路线。
- 规范过多会制造虚假精确和审美僵化。每个字段都要证明其风险收益，否则删除。
- 参考影视或艺术家作品时，应记录来源、授权和提取属性；不能把作者名字当作风格捷径。

### 容易混淆的邻近方法

- moodboard 主要帮助联想；Visual Bible 还必须包含执行规则、锚点、验收、版本和例外。
- 色彩脚本是沿时间轴的情绪模块；Visual Bible 是覆盖全项目的上位视觉契约。
