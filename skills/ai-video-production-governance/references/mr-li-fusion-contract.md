# mr-li-seedance-25 融合契约

## 1. 输入范围路由

| 输入 | 规划层 | 编译层 | 默认交付 |
|---|---|---|---|
| 完整剧本或多镜头序列 | 全局故事/信息拆解 → ShotLedger → CameraGroupPlan | 选定平台编译器 | 全部镜头组，或用户指定的镜头组 |
| 局部片段或单个续接动作 | 当前状态、容量、连续性检查 → 一个或多个局部镜头组 | 选定平台编译器 | 每个局部镜头组，详细六段式 |
| 用户明确展示偏好 | 保留对应规划范围 | 按用户指定语言/平台呈现 | 剧本输入仍记录 `TaskEnvelope.output_format = six_part` |

无论完整剧本还是局部片段，最终都进入六段式：`角色/资产锁定 → 视觉材质总控 → 镜头语言总控 → 事件节拍 → 声音 → 正向稳定约束`。区别只在规划范围：完整剧本先做全局拆组；局部片段只建立当前所需的局部镜头组。

## 2. CameraGroup 与 GenerationSegment

- `CameraGroup` 是导演规划单位，负责一个完整戏剧任务、镜头表和稳定结束状态。
- `GenerationSegment` 是平台提交单位，负责模型容量、模式和句柄编译。
- 默认一个 CameraGroup 对应一个 GenerationSegment。
- 只有已验证的模型上限、动作/信息复杂度或连续性桥接需要时才拆分。
- 拆分必须写 `split_basis`、`split_reason`、每段 `opening_state`、`ending_state`；不能删台词、改因果或用加速替代拆分。

## 3. 权威、对白和声音

- 最新被用户采纳的剧本文本是唯一权威；分析稿、建议稿和外部参考不得自动升级。
- 默认不改台词、动作、人物事实、因果和结果。所有改写建议放在提示词外，用户确认后才成为新版本。
- 普通中文对白无实测证据时按约 2.8–3.2 字/秒估算；3.5–4.2 字/秒仅可作为用户明确要求的偏快语速或已验证音频的局部估计，不能替代拆段。
- 短剧默认只保留人物对白、画外音和有物理来源的拟音；音乐、氛围床、情绪音效仅在用户或权威剧本明确要求时启用。

## 4. 资产双层映射

内部事实源至少包含：`asset_id`、`asset_type`、`asset_status`、`role`、`source_path`、`platform_handle`。平台编译器只把稳定 ID 转换为当前表面接受的 `@角色名`、`@文件名` 或后台 `{{Image N}}` 句柄；不能反向改变资产角色，也不能发明、重命名或重编号句柄。每个生成段只绑定当前实际可见或连续性所需资产。

## 5. 参考图和返工

分镜参考图不是默认步骤。只有用户明确要求制作分镜参考图或项目状态已批准该交付时，才调用参考图流程。

生成结果返工必须先有视频、截图或明确失败描述。保留已通过层，每轮只修改一个主要责任层和一个主要变量，记录证据、责任 Owner、置信度和下一检查端点。

## 6. 交付与审计

规划备注、资产清单、路由状态、风险和审计信息放在代码块外；每个镜头组（包括局部片段镜头组）拥有独立、详细、可复制的六段式代码块。正式交付可附带 manifest、文件哈希、像素/时长、重复文件和目录安全审计，但这些审计不进入模型提示词。

六段不得只有标题或套话。`事件节拍`必须逐镜写明镜头编号、时间码与
时长、景别、机位/高度/角度、焦段/透视、景深/焦点、光源方向/光质/
色温/阴影、运镜路径、动作/表演/原文台词、剪切触发、结束状态和承接。
不得用“同上”“沿用”“参考镜头表”“保持不变”等跨引用代替细节。

每个镜头窗口还必须展开镜头内 T 节拍：用 `T=起始-结束s` 在镜头组时间轴
上连续覆盖该镜头，逐段限定单个可观察动作、表演、运镜、声音同步点或
状态结果。T 段不得重叠、留空或跨越镜头边界。
在最终提示词中，T 节拍必须归属于明确的 `镜头01｜起始-结束s`、
`镜头02｜起始-结束s` 镜头块；多个镜头不得合并成无编号的事件段落。
