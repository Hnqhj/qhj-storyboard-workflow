# 交付审阅与版本

按本轮实际交付范围检查，不为纯文件整理重新读全剧或全部制作规则；审阅具体提示词/图片/视频时读取其必要模块。新内容与变化部分不能免检。没有相应文件、生成或播放能力时说明未执行项，不伪称打开或验收；普通文字使用不依赖本地维护脚本。

## 文本与媒体

- 提示词按[写作规则](prompt-writing.md)与[时长连续性](continuity-and-duration.md)核对：当前权威、范围、必要人物/信息/关系/情绪/基调、对白与动作、单段容量与整场估时、自然落点、完整实际绑定/音色、镜头写法、排版、声音原句、包装排除、准确下一起点。前后双向反查，未采用建议不能混入。
- 提示词及修正版按用户指定载体完整交付；仅文件交付时实际打开核对正文并给可访问路径，不重复粘贴。状态与下一步说明按本轮需要呈现，具体默认格式和时长沿用写作规则及用户已选范围。
- 新制或修改的图片逐张实际打开，按[图片规范](asset-image-standards.md)和[清洁验收](image-generation-clean-pass.md)检查身份、人数、结构、文字、材质、透视、画幅、真实像素、格式、边缘与残影；按实际类别验收，不把纯白站位模型当人物板/写实定帧。
- 新制人物设定板保持相应版式，动物保持完整头部/形态；机械实际部件、环境结构与关键文字保持。固定场景文字含在母图中，关联特写有明确父子关系；只有可拆卸/换用/跨场复用/独立操作的文字物件单列。
- 按[资产工作流](asset-workflow.md)核对照片用途：直接用原图时读取并核对身份与绑定事实；要求新制多视图时才检查实际生成、版式和本批角色覆盖。新制候选须经用户采用才进入正式主目录，自检不能代替采用。
- 视频实际播放所需片段，检查时间、动作完成、表演、镜头衔接、声音与连续性；静帧或导出进度不代替视频验收。
- 分镜按[分镜规则](storyboard-reference-workflow.md)核对范围/张数、镜号接续、单幅取景、机位、身份/站位、屏幕朝向、尺度、文字与媒介。命名“场次，分镜N”，存对应“分镜参考”；自审与用户采用分开。默认不绑定，明确授权时仅在指定镜头窄用途引用，不改母资产号或原绑定。
- 只插值或确定性放大到4K时明确“尺寸已达4K，但没有增加原生细节”，不冒称原生4K或模型细节增强；生成模型、真实输出规格与能力按证据报告，不写进视频正文。

## 文件与状态

剧本、提示词、资产保留旧版和明确版本关系，不覆盖唯一母版。母资产/站位文件名区分对象、用途、版本和状态；分镜交付名只用场次+镜号，版本放工作或历史目录，关联调整保留对应。

工作区保存首次生成、候选和待审稿；正式资产主目录只存用户采用、目视验收且有稳定编号的唯一主文件；可恢复历史另存。正式主目录按哈希检查同内容编号/未编号重复；按集/场有意复制是分发，不误删。场景/服装/设备改变只同步受影响关联，不自动改历史项目或晋升候选。

普通分类直接按[本地素材整理](local-asset-organization.md)执行，不套用正式采用或压缩包审计；已存在的素材不因分类而要求重新生成。

用户说“结束并审阅”，按本轮任务简报完成范围、交付位置和遗留项；涉及续作时补准确下一起点。权威版本、提示词交付、文件保存、视频生成、自检、用户采用分别记录，只把当前有用的状态写进回复。

## 正式交付与打包

用户要求正式制作交付目录或正式包时，执行以下审阅；普通文件分类沿用本地整理规则。仅明确要求压缩或 ZIP 时创建压缩包：

1. 从本次约定范围与已采用源文件建立内部预期清单，复制正式资产和约定文稿到干净暂存；台账/报告仅在用户要求时交付。清单留在交付目录外，不从待验包反推清单认可缺项。
2. 排除候选、失败过程、历史返工、临时文件、.DS_Store、._*、__MACOSX；剧情名带“失败”不代表候选。恢复材料如需交付另成明确恢复包。
3. 本批约定的正式提示词不得漏装。未匹配资产单独识别，不擅自塞入或删除。
4. 交付目录实际打开核对；压缩包在新的临时目录解包，检查安全路径、层级、数量、名称、空文件/空目录、元数据、候选泄漏、缺项、多余项、源哈希与场次副本。按实际规格验证图片像素/格式、文本编码与首尾，抽查关键媒体。
5. 实际打开产物后再报告结果；Skill包另检查版本、引用、生成版同步。缺工具或源清单时说明不能证明的部分，不声称全部合格。

## 结论分层

- 结构/文件：版本、链接、包内容、哈希、像素等机械检查，不证明语义正确。
- 文本行为：真实输入输出对照权威、范围、对白、容量、绑定、风格和授权；同轮自测如实标明。
- 独立评估：隔离上下文、最少原始资料与真实任务，保存实际输入输出；不是创建用户新任务的自动授权，也不能把见过答案的复测叫盲测。
- 实际媒体：真正生成并打开图像/视频；未生成不得声称画面质量已验证。
- 用户采用：与自检或脚本通过分开。只有相应层确已执行才报告通过，省token不能代替任一必要层。

## 可选本地脚本维护

以下命令仅适用于拥有本Skill源码与相应依赖的本地环境；单文件宿主不带脚本，仍按上述文字流程及当前工具执行可做的检查并说明限制。

正式包校验：

```sh
python scripts/audit_delivery.py /交付目录或zip --formal-delivery --manifest /审核目录/expected.json
```

本批含提示词加 `--require-prompts`；规范化母资产主目录去重加 `--canonical-assets`，分场分发目录不加。清单来自已确认交付源，不自动从待验包生成；可放临时审核目录，不强制加入项目或正式包。

清单schema_version为1；files逐项含path相对路径、kind（prompt/image/document/audio/video/file）、status（adopted）和源sha256。图片含image.width、image.height、image.format。分镜参考另标role=storyboard_reference、scene=权威场次、shot=正整数，可用status=self_reviewed；脚本核对“分镜参考”目录与“scene，分镜shot”文件名，不绕过母资产采用要求。分场包按需给required_scenes与scenes路径映射，不建无必要道具空目录。

脚本检查目录与ZIP的嵌套空目录、缺项、多余项、源哈希、基本可读性、实际图片规格、场次覆盖与ZIP安全；提示词探测仅基础检查，不能代替实际对白/绑定/节奏审核。

版本发布先审阅源规则，再记录review-snapshot.json内容哈希；后续变化使快照失效，不为消除报错自动刷新。单文件版由scripts/build_runtime.py生成，禁止手改；依赖requirements-test.txt仅用于本地验证。
