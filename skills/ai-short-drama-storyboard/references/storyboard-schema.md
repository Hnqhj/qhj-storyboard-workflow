## 镜头记录

每个镜头在后台使用以下完整字段。前台按用户要求合并重复字段；缺少信息时写“待确认”或明确假设，不要留空：

| 字段 | 内容要求 |
|---|---|
| `shot_id` | `S01`, `S02A` 等稳定编号 |
| `beat` | 对应剧情 beat 和镜头目的 |
| `duration` | 秒数；按动作、台词和停留独立定时，不按固定模板分配 |
| `framing` | 远景/全景/中景/近景/特写/过肩 |
| `angle` | 平视、俯拍、仰拍、侧面、主观等 |
| `camera_move` | 固定、推、拉、横移、跟拍、手持；只选一个主运动 |
| `lens` | 焦段或镜头视角感（如 28mm 广角、50mm 纪实、85mm 压缩）；说明它服务的空间/关系任务 |
| `focus_dof` | 对焦主体、景深范围、拉焦触发；不以“电影感景深”代替具体焦点 |
| `blocking` | 人物入画、站位、视线和出画方向 |
| `start_state` | 承接前镜的姿态、朝向、视线、手部、道具和环境状态 |
| `action` | 一个主要可见变化，按开始 → 变化 → 结束写清楚 |
| `performance_beat` | 台词对应的说话者微动作与倾听者回应；无对白时写情绪可见信号 |
| `end_state` | 本镜结束时可供下镜复现的具体状态 |
| `dialogue_or_vo` | 短对白、旁白、字幕或无；标注说话者和语言 |
| `lighting` | 主光/辅光/轮廓光或实景光源、方向、软硬、色温、阴影与反射逻辑 |
| `sound` | 环境声、动作声、音乐节拍 |
| `bridge_cue` | 下镜承接的动作/手部、视线、道具、背景运动、声音、遮挡或光线 |
| `transition` | 硬切、动作承接、声音先行等；说明为何此处需要切镜 |
| `continuity_ids` | 角色、场景、道具和服装 ID |
| `KEYFRAME_PROMPT` | 可复制的静态首帧提示词 |
| `VIDEO_PROMPT` | 可复制的运动提示词 |
| `NEGATIVE_PROMPT` | 本镜头特有的负面约束 |

## 连续性规则

### 角色

- 同一角色的年龄段、脸型、发型、主色服装和固定饰品默认不变。
- 变化必须有剧情原因，并在 `continuity_note` 中记录，例如“湿发由 S02 的雨戏导致”。
- 同一镜头超过两人时，指定主角色、辅角色和背景角色，避免模型平均分配注意力。

### 走位与视线

- 记录屏幕方向：`C01 frame left, looking right`。反打镜头要明确是否使用 180 度规则。
- 景别策略：全景/中景/近景承担默认叙事、对白和调度；特写仅用于强烈动作或能力峰值、决定性眼神、关键受力/接触或不可替代道具证据。位置转变先用全景或中景交代；推镜头不直接推到人脸，近景默认腰部以上并保留肩背、手势、视线或关系对象。
- 对话覆盖优先保留能说明关系和空间的双人镜头；是否增加单人反应镜头由台词长度、语义落点、冲突等级和信息增量决定。短句、语气词或无需他人接收的台词可不切反应；需要反应时，每条反应必须改变信息、关系、权力、行动或悬念，且不要重复相同表情。
- 需要越轴时，先用正面或移动镜头建立新轴线，再切反打。

### 道具与环境

- 道具首次出现时创建 ID，例如 `P01=cracked phone`；后续只改变状态，不重写外观。
- 记录时间、天气、主光方向和背景活动。生成同一地点的连续镜头时，保持至少两件可识别背景物。
- 手机、电脑、标牌等屏幕默认使用“不可读文字”，把准确信息留给后期合成。

### 关系与表演

- 把人物关系也视为资产：屏幕左右、共同朝向、距离、共享支撑物/活动、说话者与倾听者职责。除非画内完成变化，跨镜保持不变。
- 台词按语义停顿绑定微动作；说话者和倾听者的动作错开，避免同时转头、同时点头、同时吸烟或每句都改变姿势。
- 每次切镜至少继承一个明确承接信号。后镜 `start_state` 必须等于前镜 `end_state`，或明确从已开始的动作中段接入。
- 用具体材质和环境状态保证画面统一：风向、烟雾、雨后水迹、主光方向、移动灯光方向都需要连续。

## 剪辑与生成检查

### 生成前

- 先生成角色定妆图、表情参考和场景定场图。
- 从一集里优先挑 3–5 个连续镜头做小样，不要一次生成整集。
- 图生视频先锁定首帧；如果首帧已出现错误，不要用视频提示词硬救。

### 生成后

- 人脸/服装/道具与上一镜头是否一致。
- 主动作是否在前 1 秒内开始，结束状态是否可剪接。
- 台词、停顿、微动作和听者回应是否逐段对齐，是否存在无依据的同步动作。
- 每对相邻镜头的 `end_state → start_state` 是否一致，`bridge_cue` 是否真的出现在画面或声音中。
- 手、眼神、脚步和道具接触是否自然；是否出现无来源的第二动作。
- 是否出现闪烁、身份漂移、背景跳变、错误文字、logo 或水印。
- 对白是否适合当前镜头的口型时长；长台词拆为 VO、反应镜头或后期配音。
- 组级正向稳定约束是否先说明人物关系、共同朝向、道具和环境不变项；负面词是否只补充实际风险。

### 失败时的优先修正顺序

1. 缩短动作并拆成两个镜头。
2. 用参考图或首帧锁定人物和场景。
3. 降低同时出现的人数和道具数量。
4. 把复杂运镜改为固定机位或单一推镜。
5. 把可读文字、复杂手势和精确口型移到后期。

## 建议输出结构

```markdown
## 制作假设
...

## 剧本拆解
| beat | 戏剧目的 | 可见行为 | 信息/钩子 |
|---|---|---|---|

## 连续性圣经
### 角色
| id | 外观固定项 | 服装 | 性格外化动作 | 禁变项 |
|---|---|---|---|---|

### 场景与道具
| id | 空间/时间 | 光线 | 固定背景 | 道具状态 |
|---|---|---|---|---|

## 分镜表
| shot_id | beat | duration | framing/angle | camera_move | blocking/action | dialogue_or_vo | lighting/sound | continuity_ids |
|---|---|---:|---|---|---|---|---|---|

### S01
**KEYFRAME_PROMPT**
...

**VIDEO_PROMPT**
...

**NEGATIVE_PROMPT**
...

## 测试顺序与风险
...
```

如果用户要求 JSON，使用同名 snake_case 字段输出数组；提示词中的换行可保留为字符串，不要混入 Markdown 表格。
