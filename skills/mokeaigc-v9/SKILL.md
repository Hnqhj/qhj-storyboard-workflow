# MOKE 世界观构建

把一个创意火花发展成**被生活、使用和环境压力塑造出来的世界**，再用多张彼此连贯、功能不同的电影静帧让它被看见。

```text
创意/参考证据
-> 世界承诺
-> 连续性 Bible
-> 方面矩阵
-> 平台中性静帧
-> 输出模式
-> 平台或生产链交接
```

核心判断：可信世界不是“设计得很多”，而是能从行为、材料、磨损、路径、生态、空间使用和前后痕迹中看出它怎样运转。

## 所有权与边界

本 Skill 只拥有**多方面世界发现板**：从一个世界种子或参考图，发展共享规则并选择不同世界功能的静帧。

不拥有：

- 一张普通电影感图片：交给 `$cinematic-ai-image-prompt-library`；
- 同一个场景/核心画面的多机位构图板：交给 `$cinematic-ai-image-prompt-library` 的 same-scene composition 分支；
- 最终的世界生产设计、空间证据、介质和图像模型打包：交给 `$world-visual-development-director`；
- 角色/生物/武器/建筑的长期身份锁定：交给 `$character-continuity-bible` 或对应设计 Skill；
- 剧本镜头表和视频运动：交给 `$professional-storyboard-director`、`$ai-video-prompt-director` 或平台视频 Skill；
- Midjourney、GPT Image、Nano Banana 等当前语法和参数：交给当前 platform adapter；
- 已生成九宫格的确定性拆格：用户明确要求后交给 `$curate-image-grid`。

不要因为用户说“九张”就自动判定为世界观。先判断九张之间变的是**世界功能**还是**同一场景的拍法**。

## 指令优先级

冲突时按以下顺序：

1. 用户明确指定的内容、数量、介质、画幅、语言、平台和禁区；
2. 上游 `world-visual-development-director` 已批准的世界承诺与介质；
3. 参考图中可见或强证据支持的事实；
4. 当前项目的连续性 Bible；
5. 本 Skill 的默认值。

固定相机、焦段、胶片、负面词、双语格式或平台参数都不得覆盖更高优先级。

## 默认值

用户给出一个有意义的火花就直接开始，不先发长问卷。只有会改变核心世界方向的互斥缺口才追问。

```yaml
platform: generic
aspect_ratio: 16:9
aspect_count: 9
output_mode: compact
base_rendering: cinematic observational realism
capture_profile: adaptive
```

若由 `$world-visual-development-director` 调用，服从它选择的 6/9 数量和介质。用户指定子集时，只做该子集，不补回九张。

## 工作流

### 1. 锁定世界承诺与证据边界

先用一句话回答：

```text
观众从任意一帧中首先应该理解这个世界的什么？
```

再锁定：地理/气候压力、时代与技术、居民/生态、材料与制作、生活方式、情绪承诺、用户禁区。

参考图只提取可见或强支持的证据：主体、身体覆盖、地形、建筑、尺度、颜色、光、材料、磨损、天气、劳作、仪式或生态。把内容标为：

```text
observed | strongly implied | creative extension | unknown
```

不要照抄参考图构图，也不要把创作延展写成原图已经证明的文化事实。

### 2. 建立连续性 Bible

在写提示词前，内部建立紧凑 Bible：

- 地理、气候、时代/技术；
- 居民特征与身体覆盖；
- 标志材料、建筑语法、工具/交通；
- 动物生态、 recurring symbol；
- 颜色所有权、灯光逻辑、天气/空气、表面质感；
- `forbidden_drift`：不允许无理由出现的新技术、物种结构、服装轮廓、建筑材料、气候或色彩系统。

条目必须可见、可生成。写“盐霜化的芦苇披风以氧化铜扣固定”，不要写“这个文化重视坚韧”。

### 3. 规划方面矩阵

从九个世界功能中选择用户要求或当前项目最需要的方面：居民、动物、建筑、地景、日常、迁徙交通、声音文化、权力压力、私密肖像。

每帧先填：

```text
方面与叙事问题
场景和当前可见动作
前景 / 中景 / 背景
连续性锚点（通常至少 3 个）
机位高度、主体距离、视场意图
光线、天气、材料
情绪强度
之前/之后痕迹
本帧最可能的通用失败
```

锚点自然复现，不把整本 Bible 粘进每条提示词。不同帧不能重复同一主地点、主动作和构图任务。距离、机位和强度的变化由叙事功能决定，不按固定焦段配额。

### 4. 写平台中性静帧

每帧按可见因果组织：

```text
主体与当前动作
+ 空间关系和前中后景
+ 2–3 个关键连续性锚点
+ 相机位置、主体距离和视场/景深意图
+ 有动机的光、天气、材料和磨损
+ 前后痕迹
+ 1–4 个当前画面的定向约束
```

镜头像在现场发现事件，而不是安排商品展示。禁止排排站、空建筑效果图、生物图鉴、泛化海报、随机文化符号和只靠雾制造纵深。

### 5. 适配摄影与风格

先决定观看功能、相机位置、主体距离、空间关系、遮挡和景深，再决定是否需要焦段数字。焦段只是视场意图锚点；它不单独决定透视，也不保证生成模型遵循真实摄影物理。

数字相机与胶片响应要写成明确的 emulation，不把数字采集和字面胶片拍摄混写。皮肤细节只在近距离、清晰可见的人脸上使用。

用户或上游已锁介质/风格时，只保留世界机制，不保留冲突的相机、胶片、真实摄影或 `no CGI` 默认串。

### 6. 选择输出模式

- **Planning-only**：只给世界概念、连续性 Bible、方面矩阵和未决选择；用户尚未批准方向时使用。
- **Compact（默认）**：世界名、2–3 句概念、简洁连续性锚点、每方面一个视觉意图和一条完整提示词。
- **Production**：用户明确要双语、拆分 Camera/Lighting、完整生产字段或平台成品时才使用。

不要默认输出重复的中英文、摄影、灯光和完整提示词四份同义内容。

### 7. 平台和生产交接

世界语义先稳定，再交平台 adapter 改语法。保留主体、动作、空间、锚点、光材质和约束；只改变参数与句法。

若进入视频，只交接：

```text
world promise
3–6 visual laws
geography / climate
material and color ownership
approved recurring assets
location pressure and action affordances
continuity risks
```

不要把九条静帧提示词整段塞进一个视频提示词。

## 静默验收

交付前逐项修正，不把清单原样展示给用户：

1. 任务确实是世界的不同功能，不是同场景多机位；
2. 数量和子集与用户要求一致；
3. 每帧有不同叙事问题、当前动作和前后痕迹；
4. 连续性锚点足以证明同一世界，但没有造成机械重复；
5. 气候、技术、物种、服装、材料、建筑、颜色和光没有无理由漂移；
6. 前中后景、遮挡、尺度和距离衰减证明真实空间；
7. 光、阴影、反射、天气介质和材质响应一致；
8. 机位、距离、视场和景深不自相矛盾；
9. 平台语法没有被跨平台复制，也没有空参数或自造参数；
10. 输出模式没有比用户实际需要更重。
