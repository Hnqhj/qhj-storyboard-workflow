# 主镜反推机位

## 使命

不要先平均地“拍全剧情”，再给每句台词配一个镜头。先找到观众必须记住的关键画面，再从这些画面反推出可成立的空间、人物调度和镜头组。

> “观众实际看到和感受到的，是否等于创作者想传达的。”

## 触发与边界

在以下情况调用：

- 分镜像机械覆盖：全景、正反打、特写平均分配，没有真正的主镜；
- 已经想到一张很强的画面，但不知道人物该站哪、轴线在哪、前后镜头怎么接；
- 两人或多人场景出现左右关系、阵营关系、眼线或空间理解混乱；
- 画面平、焦点散、景别或机位高度只凭“好看”和“权力感”决定；
- 需要先出一份机位蓝图，再交给完整分镜或 AI 视频提示词流程。

不拥有：

- 宏观 hook / 转折 / 高潮结构：交给 `$video-structure-design`；
- 每镜新增什么观众信息：先由 `$shot-information-progression` 提供信息骨架；
- 完整分镜表、镜头数和可画帧：交给 `$professional-storyboard-director`；
- 通用镜头语法、连续性、运镜和声画设计：由 `$cinematic-audiovisual-language` 校验；
- 最终平台提示词：交给 `$ai-video-prompt-director` 或对应模型适配 Skill。

## 方法解释

“主镜”不是大全景，而是一个段落中承载最多必要信息、关系或情绪转折的关键画面。主镜先决定观众要看到什么，再约束人物位置、道具关系、轴线、机位区和连接镜头。这样得到的是由意义驱动的镜头系统，而不是机位词汇的堆砌。

### 连续长镜头负荷门

一镜到底必须先通过空间与运镜可行性检查，再安排动作。对30秒以内的短片，默认只保留一个连续前进路线、一个主要冲突和一个结尾揭示；环绕、跟拍、低机位、穿越遮挡等都算运镜模式变化，最多保留两次。每次模式交接必须由可见事件触发：人物转身、冲撞、跌倒、穿门或目标改变方向。禁止镜头无动机地从环绕突然切入跟拍。

场景切换必须有完整的物理遮挡或连续空间通道，并保持遮挡前后的运动方向、光色和主体朝向一致。若空间没有纵深、回旋半径或可供遮挡的前景物，先改舞台，不要继续堆叠运镜术语。

### 场景替换与实拍基底

当原场景过于封闭、像游戏关卡或限制跟拍时，优先替换为具有长轴、层次和自然遮挡的真实场所，例如暴雨中的高架桥下层、废弃火车站站台、滨河防洪隧道、山地公路服务区或大型温室。场景选择必须提供：连续行进路线、至少一个前景遮挡物、一个可改变高度或方向的地形节点、以及结尾揭示所需的远景深度。不要用“更多霓虹、更多粒子、更多UI”弥补空间贫乏。

若用户要求游戏风格，只把它登记为击杀瞬间的局部效果属性；主镜、人物表演、镜头运动和环境材质仍按电影实拍逻辑设计。

参考《动物世界》式的视觉冲击时，优先把“帅气”落实为可见空间关系：拉开摄影机、子弹、目标和背景的距离，利用前中后景视差、斜向构图、穿越障碍物和远距离反应镜头制造冲击。击杀后的彩色血浆必须成为接触点的结果，并在镜头中经历喷出、飞散、落地三个阶段；结尾主镜应留下一个新的威胁信息，而不是只停在角色脸部特写。

## 执行流程

### 1. 写场景契约

先写四行，不能直接选镜头：

```text
实际事件：发生了什么可见变化？
关系变化：谁观察、压迫、回避、结盟或失去主动？
观众任务：必须看见、理解、记住什么？
情绪结果：段落结束时观众应处于什么状态？
```

如果“观众任务”仍不清楚，先调用 `$shot-information-progression`。

### 2. 按信息段切场，不按台词切

把场景拆成发现、确认、反应、决定、行动、后果等信息段。每段只写一个主要变化。相邻两段没有新信息或关系变化时，先合并，不用景别变化伪装进展。

### 3. 为关键段落选主镜

每个段落最多先选 1 个主镜；短场景通常只需 1–3 个。主镜必须至少完成两项任务：

- 同时交代人物、道具或环境关系；
- 让权力、观看、阻隔、靠近或疏离直接可见；
- 把发现、决定、接触或后果变成不可替代的图像；
- 为前后镜头提供明确的焦点或运动交接。

若删掉这张图仍不影响理解与记忆，它不是主镜。

### 4. 从主镜反推舞台

对每个主镜反推：

```text
人物/道具位置 -> 身体朝向 -> 视线/行动方向 -> 主关系轴
-> 可用机位区 -> 不能进入的误导区 -> 前后连接所需的位置或动作
```

多人场景先确定当前最重要的关系，不平均维护所有轴线。机位若会把敌对者误读为同一阵营，或把观看关系翻转，标记为禁区。

### 5. 让景别和视高承担任务

景别按信息范围、亲疏、视角和节奏决定；视高按人物目光、观众位置、构图需求、焦点连续和段落变化决定。不要把“低机位=强、高机位=弱”当唯一公式。

每个镜头只填一句：

```text
这个景别/视高让观众更清楚地看见 ______。
```

填不出来就回到主镜任务，而不是继续加镜头术语。

### 6. 设计眼动、空间和动势

- 第一焦点必须落在当前信息载体上；
- 相邻镜头记录焦点入口与出口，默认避免无意义的大幅上下跳；
- 通过可见的面、前中后层、遮挡和尺度关系制造空间，而不是只加背景细节；
- 先用大色块或箭头检查运动方向，再补姿态；
- 同向延续用于顺滑，反向、停顿或高度突变只在段落需要顿挫时使用。

### 7. 只补必要的连接镜头

连接镜头只能完成明确任务：建立空间、交代视线、证明动作、承接焦点、揭示反应、压缩时间或产生蒙太奇意义。不要为了“覆盖安全”补一圈重复正反打。

跳轴前先写收益：故事、视角、构图、节奏或心理异常。没有可见收益就不跳；有意跳轴时，让关系或情绪变化成为观众能感到的结果。

### 8. 做观众回放

遮住文字，只按镜头顺序回答：

1. 我第一眼看哪里？
2. 我知道人物和物体在哪里吗？
3. 我理解谁在看谁、谁推动了变化吗？
4. 每一切是否带来新信息、视角或意义？
5. 主镜是否真的是最该记住的画面？

任何一项失败，优先重做主镜或舞台，不用更多镜头补救。

## 源材料中的应用

- 两人对话：主关系轴约束左右与眼线，正反打服务压力和观看关系，而非机械轮流说话。
- 三人场景：先确定主要冲突，避免错误机位把不属于同一阵营的人视觉分组。
- 道具发现：让道具、发现者、指出者和处理者形成因果镜头组，主镜承载“发现或决定”，连接镜头只补必要证明。
- 主观视角：通过“角色反应 -> 他看到的对象”建立体验，不把 POV 镜头当唯一主观化手段。

## 输出格式

```text
场景契约：
- 实际事件：
- 关系变化：
- 观众任务：
- 情绪结果：

信息段：A -> B -> C

主镜蓝图：
1. 段落 / 主镜描述 / 必要信息 / 关系与焦点 / 删除代价

舞台与轴线：
- 位置、朝向、视线/行动方向：
- 主关系轴与可用机位区：
- 误导区/允许突破及收益：

连接镜头：
1. 来源主镜 -> 镜头任务 -> 景别/视高理由 -> 焦点/动势交接 -> 下一主镜

连续性风险：
- 左右/眼线/阵营/焦点/动势/空间：

交给完整分镜的约束：
- 必须保留：
- 可以自由变化：
```

## 质量门

- 主镜是“主要信息画面”，不是默认大全景；
- 关键镜头先于覆盖镜头；
- 机位来自画面任务与空间关系，不来自炫技清单；
- 景别和视高都有可说清的观众任务；
- 每个连接镜头都有独立功能；
- 轴线突破有明确、可感知的收益；
- 最终蓝图能无歧义交给 `$professional-storyboard-director`。

详细决策矩阵见 `references/master-shot-decision-system.md`。

## 不要这样做

- 按每句台词切一镜；
- 先画平面图，再被平面图限制到没有主镜；
- 把每个人平均拍一遍；
- 用景别变化冒充信息变化；
- 因为“构图更酷”无意识跳轴；
- 把构图模板、摄影参数或名导名字当成专业方法本身。
