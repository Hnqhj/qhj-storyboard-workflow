# 跨镜头一致性矩阵审计

## R — 原文（Reading）

> “我们要整个把这些图排在一起，最好是排在一起，看一下它的灯光是否有问题……需要非常专业的人来做风格一致性的校验。”
>
> — MokeLMa，视频 01，00:59:00–00:59:09；视频 03，00:15:50–00:16:38

---

## I — 方法论骨架（Interpretation）

一致性不是逐张判断“好不好看”，而是在同一叙事序列或品牌系统中判断“是否仍属于同一世界”。
审计必须先指定获批锚点；没有锚点，只能得到互相之间的差异，无法判定谁在漂移。
把镜头按时间线并排，再以身份、状态、空间、光照、色彩、材质、成像、运动等维度建立矩阵，防止“感觉不统一”变成无方向返工。
差异不等于错误：场景转换、情绪推进和平台适配允许有意变化；只有违反 Bible、连续性或预期过渡的差异才叫漂移。
每个漂移都要分级：可接受、局部可修、需要重建约束、身份/叙事冲突必须重做。
修复优先选择影响半径最小的路线；能局部调色、遮罩或合成解决的，不先整镜重抽。
修复后必须回到同一矩阵复审，不能把“做过处理”当成“已经匹配”。

---

## A1 — 课程中的应用（Past Application）

### 案例 1：用获批关键图校正短片中的漂移镜头

- **问题**：同一短片中，部分生成画面的调子与已经确定的画面发生偏移。
- **方法论的使用**：讲者先把镜头排在一起检查，把确认图作为锚点，再将其色彩/光照特征迁移到漂移图，并配合去杂色与超分处理。
- **结论**：修复不从“重新抽一张”开始，而从锚点、漂移维度和最小修改开始。
- **结果**：该手段被用于讲者提到的特朗普短片；课程只局部展示，没有全片盲评或观众测试。
- **出处**：视频 01，00:58:51–01:00:28；对应案例池 `c11`。

### 案例 2：跨平台生成后做质感与感官匹配

- **问题**：来自不同平台的沙漠或港式灯光镜头过于干净、油腻，颗粒、锐度、饱和度和高光感不一致。
- **方法论的使用**：讲者逐项调整高光/泛光、颗粒、柔化、饱和、色带和深度分层，而不是只套一个统一滤镜。
- **结论**：平台差异要拆成可见维度处理；“统一加颗粒”不能代替材质、光照和空间检查。
- **结果**：现场前后对比更接近讲者设定的质感，但手部等生成缺陷仍存在，也没有证明“更真实”是普遍评价。
- **出处**：视频 01，01:12:45–01:16:49；视频 02，01:34:29–01:41:34；对应案例池 `c14`。

## A2 — 触发场景（Future Trigger）

### 用户会在什么情境下需要这个 skill？

1. 多个镜头、海报、发布会视频或直播包装单看合格，合在一起却像不同作品或不同品牌。
2. 同一角色在镜头间出现脸型、服装、道具状态、渲染写实度、材质或比例漂移。
3. 同一场景的主光方向、色温、阴影、接触关系、曝光或空气层在切换时跳变。
4. 项目混用多个生成模型、软件、供应商或实拍素材，需要统一 sequence QC 与修复优先级。
5. 用户只会说“不统一”“AI 味太重”“像贴上去的”，需要把感觉转成可定位的差异矩阵。

### 语言信号

- “每个镜头都挺好，为什么剪起来散了？”
- “帮我做跨镜头一致性检查 / 风格连续性校验。”
- “Run a cross-shot consistency audit and produce a repair matrix.”
- “Match these AI shots to the live-action plate / approved keyframe.”
- “同一角色忽写实、忽三渲二，光也接不上。”

### 与相邻 Skill 的区分

- `visual-calibration-loop` 提供情绪、色彩、光线和关键帧锚点；本 Skill 在已有素材上定位偏差并复审修复。
- `entity-continuity-system` 提供角色、道具、商品与场景的身份和状态基准；本 Skill 检查实际镜头是否遵从。
- 本 Skill 只审计已经入选并进入序列的资产，不负责前期定调、建库或候选筛选。

## E — 可执行步骤（Execution）

激活后，agent 不得直接给“统一一下色调”的笼统建议；必须输出锚点、矩阵、严重度、修复路由和复审结论。

### 1. 锁定审计范围与观看条件

- 收集要审计的镜头/资产、正确播放顺序、镜头 ID、版本、来源工具、场景和时间状态。
- 在同一显示变换、色彩空间、分辨率/缩放与播放速度下建立 contact sheet 和时间线；把代理压缩、错误 LUT 或显示设置造成的假差异先排除。
- **完成标准**：每个项目项都有唯一 ID 和顺序，审计者能在同一条件下并排或连续观看。

### 2. 指定批准锚点与允许变化

- 为全局风格、每个场景、关键角色和主要光照状态指定获批锚点；记录批准人、版本和它代表的标准。
- 同时记录有意变化，例如昼转夜、情绪降温、梦境变形或平台尺寸适配，避免把叙事变化误判为漂移。
- **判停条件**：若没有获批锚点或 Bible，停止“合格/不合格”判定，转到 `visual-calibration-loop` 或 `minimum-visual-bible`；此时只能交付差异清单。
- **完成标准**：每个被审计镜头都能指向一个锚点和一组允许变化。

### 3. 建立一致性矩阵

至少检查以下维度；不适用项要标记 `N/A`，不能静默跳过：

| 维度 | 可观察检查项 |
|---|---|
| 身份与状态 | 脸型、身体比例、发型、服装、道具、损伤、污渍、液面、标签、时间状态 |
| 空间与连续性 | 轴线、视线、左右关系、尺度、入口/出口、背景几何、遮挡、位置承接 |
| 光照 | 主光方向、软硬、光比、色温、实景光源、接触阴影、反弹光、环境包裹 |
| 色彩与调性 | 白平衡、曝光、黑白点、肤色、饱和度、主辅色、段落过渡 |
| 材质与细节 | 粗糙度、通透度、反射、纹理尺度、边缘质量、磨损与局部缺陷 |
| 成像与风格 | 写实/三渲二程度、锐度、景深观感、颗粒、泛光、动态范围、压缩痕迹 |
| 运动与时间 | 动作方向、速度、节奏、运动模糊、姿态承接、口型/表情连续 |
| 品牌/文字（如适用） | Logo、字体、字号层级、留白、品牌色、文案与安全区 |

- **完成标准**：每个镜头×维度单元格都有证据注释和严重度，不以一条总评替代矩阵。

### 4. 分离“有意差异”与“非预期漂移”

- 对每个差异询问：是否有 Bible/剧情/场景状态依据？是否沿时间线形成可理解过渡？是否由批准人明确同意？
- 使用四级严重度：`0 匹配`、`1 有意或可容忍差异`、`2 可局部修复漂移`、`3 身份/叙事/空间冲突`。
- 对 `2`、`3` 级写出可观察证据，例如“镜头 S14 的鼻影向右，锚点与相邻镜头向左”，不写“光不对”。
- **完成标准**：每个非零项都有 `依据 / 严重度 / 影响 / 责任路由`。

### 5. 按影响半径选择修复路线

- **L1 局部后期**：曝光、白平衡、局部饱和、锐度、颗粒、色带、遮罩、边缘和轻微材质差异。
- **L2 定向匹配**：参考图/批准帧色光迁移、分层 relight、深度遮罩、接触阴影、局部合成、状态资产替换。
- **L3 约束重建**：身份、比例、轴线、空间、动作或关键光照关系错误时，回到 `entity-continuity-system`、`constraint-input-router` 或批准 layout 重新生成/渲染。
- **L4 叙事裁决**：若两个镜头分别漂亮但无法在叙事上并存，由具名导演/美术/品牌负责人决定删、换或改段落，不能让算法平均折中。
- **完成标准**：每个问题只有一个主修复路线、负责人、预计代价和复审条件。

### 6. 对真人/AI 混合镜头执行强制光照检查

- 除色调外，必须检查主光方向、填充、反弹光、遮挡、接触阴影、环境反射、空气层、景深关系和边缘融合。
- 只套同一 LUT 不能通过此门；主体像“贴在背景上”时优先重建光照/合成关系。
- **完成标准**：在静帧与播放状态下均不存在方向冲突或缺失接触关系；无法确认的项标记风险，不伪造“已匹配”。

### 7. 修复后用同一矩阵回归审计

- 保留修复前后版本，以相同锚点、观看条件和矩阵重新评分；不得换标准来让结果通过。
- `3` 级问题未清零不得交付；`2` 级遗留必须得到具名批准并写明风险；`1` 级需标注为何是有意变化。
- **完成标准**：输出前后差异、通过项、遗留项、批准人和最终 `PASS / CONDITIONAL PASS / FAIL`。

### 最小输出契约

- 有序 contact sheet / 时间线和版本表
- 批准锚点与允许变化表
- 镜头×维度一致性矩阵
- 0–3 严重度、证据与责任路由
- L1–L4 修复计划
- 修复前后回归结果与最终判定

## B — 边界（Boundary）

### 不要在以下情况使用此 skill

- 只有一张独立图片、没有序列或品牌系统关系；做单张质量评审即可。
- 尚未决定风格、角色或场景方向；先用 `minimum-visual-bible` 与 `visual-calibration-loop` 建立标准。
- 团队正在从大量候选中挑选方案；那是 `bounded-explore-select`，不是一致性审计。
- 问题是剧本、镜头覆盖或角色设计本身不足；一致性矩阵不能把错误方向修成好作品。

### 课程警告的失败模式

- 每个镜头单独追求“惊艳”，导致同一角色忽写实、忽三渲二，材质、通透度、色光不断变化。
- 只看当前镜头，不与前后镜头或获批关键帧并排。
- 把无瑕、平滑、均匀锐利当成电影质感，再用统一颗粒掩盖所有问题。
- 真人与 AI 只对同一色调，不对主光、遮挡、反弹与接触关系。

### 讲者盲点与时代局限

- “更有人味”“更真实”是目标相关的审美判断，不是颗粒、柔化或过曝越多越好；必须服从批准锚点与媒介目的。
- LUT 或自动光照传递只能作为候选修复，不能证明物理光照一致；最终看可见关系和合成证据。
- 不同平台、色彩管理、压缩和显示器会制造假漂移；审计前必须统一技术观看条件。
- 课程案例主要是个人项目和局部演示，缺少完整观众测试；严重度阈值要由项目团队批准。

### 容易混淆的邻近方法论

- 一致性不等于所有镜头完全相同；叙事情绪、昼夜和镜头功能需要有设计的变化。
- 风格匹配不等于身份连续；同色调的两张脸仍可能不是同一角色。
- 摄影参数写在提示词里不保证物理准确；审计依据应是可见透视、光照和可靠元数据，而不是提示词中的数字。
